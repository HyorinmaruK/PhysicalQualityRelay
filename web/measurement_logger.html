Give the spare ESP32 a job

With the servo gone, a spare ESP32 is free. Use it as the measurement station: it reads the caliper or a gauge and sends each number straight into the logger over USB (the "Connect ESP32" button on tab 1, via Web Serial). You press one button on the bench, the number lands in the CSV, and the optional QAPASS 16×2 LCD shows it. Less typing, fewer transcription mistakes.

You still don't have to build this. Pure manual — read the caliper, type the number on tab 1 — needs no wiring at all, and the page does the maths. The ESP32 is a convenience and gives the spare board something to do.
Whatever the source, the number is evidence: the operator-confirmed caliper reading stays authoritative, and the repo never lets a raw sensor value set a verdict on its own.

Option A — potentiometer / linear gauge (reliable)

A linear slide potentiometer is a cheap position gauge: easy to wire and always works, but lower precision than your digital caliper and it must be calibrated. Good for a second axis (say height) or as a backup. It reuses the repo's existing potentiometer_to_mm() in qualityrelay17/hardware_ingest.py and the /hardware/caliper-reading endpoint.

Calibrate first. Measure at least five known positions against the real caliper, then set ADC_MIN/ADC_MAX and MM_MIN/MM_MAX in the sketch. Without that the millimetres are meaningless.

Firmware: firmware/measurement_station/esp32_measurement_station.ino (default mode). S3 pins GPIO4 (pot/ADC1), GPIO5 (button), GPIO8/GPIO9 (I²C). For a classic ESP32 use 34/32/21/22.

Mounting a wide ESP32-S3 (Freenove / N16R8). These boards cover the whole half of the breadboard, so there is no free row next to the pins. Three ways to handle it:
  1. Recommended, no solder: leave the board off the breadboard (as drawn) and use female–male jumpers — female end onto the ESP32 header pin, male end into the breadboard. The breadboard holds only the pot, button, LCD and the rails.
  2. Two breadboards: push two breadboards together long-edge to long-edge; the board straddles the seam and each pin row gets free holes on its outer side. Then wire like a normal board.
  3. Solder: solder the board onto a piece of protoboard, or solder a short pigtail harness to the pins you use (GPIO4, GPIO5, GPIO8, GPIO9, 3V3, GND). Only if you want it permanent — the jumper method needs no cutting or soldering.

Power & how to run

No external power supply needed. The USB cable powers the ESP32, and the pot, button and LCD together draw only tens of milliamps — well within USB. (The external 5 V supply was only for the servo, which you removed.)
  1. Wire with USB unplugged (pot and button first; LCD optional, skip for the first test).
  2. Multimeter check: the wiper (GPIO4 wire) reads 0 → 3.3 V as you slide the gauge; if reversed, swap pot pin1/pin2. The pot's top pin is 3V3, never 5V — more than 3.3 V on a GPIO damages it.
  3. Arduino IDE: install "esp32 by Espressif" (Boards Manager). Board = ESP32S3 Dev Module. For the N16R8 set Flash Size 16 MB and PSRAM "OPI PSRAM"; if you use the board's native-USB port, also set "USB CDC On Boot: Enabled". Select the serial port that appears.
  4. Open esp32_measurement_station.ino, keep READ_SOURCE = SOURCE_POT and USE_LCD = 0, and Upload. If it will not connect, hold BOOT, tap RESET, release BOOT, and upload again.
  5. Serial Monitor at 115200 → # QRM ready. Press the button: a number prints each press, with a # adc=… line. Slide the gauge and the number changes. Garbled/repeated symbols? Wrong baud — set the Monitor's baud dropdown (bottom-right) to 115200. Only see the ROM boot log (ending entry 0x4…) but no # QRM ready, on a /dev/cu.usbmodem… (native-USB) port? Set Tools → "USB CDC On Boot: Enabled" and re-upload — on the native port the app's serial needs CDC on (otherwise it goes to the UART0 pins).
  6. Calibrate: at ≥ 5 known caliper sizes, record the # adc= value, then set ADC_MIN/ADC_MAX and MM_MIN/MM_MAX in the sketch and reflash so the printed mm match the caliper.
  7. Auto-log: Web Serial needs a secure context, so serve the page — from the repo folder run python3 -m http.server 8000 and open http://localhost:8000/web/measurement_logger.html in Chrome or Edge. Close the Arduino Serial Monitor first (only one app can hold the port). Click Connect ESP32, pick the port, press the button — the value fills the field; then "Add specimen to log".
"Failed uploading: no upload port provided"? The sketch compiled — the IDE just has no port selected (Tools → Port is empty). Work through: (1) use a USB data cable, not charge-only; (2) these S3 boards have two USB-C ports — for the first upload use the one marked UART / COM; (3) install the USB-serial driver (Freenove S3 = CH343/CH340; some boards = CP210x); (4) if still no port, enter download mode: hold BOOT, tap RESET, release BOOT, then pick the port that appears; (5) for the N16R8 use ESP32S3 Dev Module with Flash Size 16 MB, Flash Mode QIO, PSRAM OPI PSRAM — avoid the "octal flash / WROOM2" preset, which sets octal flash and can stop it booting.
Still only the boot log, or it keeps repeating (reset cause RTCWDT_RTC_RST)?
  1. Boot loop = wrong Flash Mode. The panic assert failed: __esp_system_init_fn_init_flash … (flash_ret == ESP_OK) means the flash could not initialise. Set Flash Mode = QIO 80 MHz (the N16R8 flash is quad, not octal/OPI), Flash Size 16 MB, PSRAM OPI PSRAM, and set "Erase All Flash Before Sketch Upload: Enabled" once, then re-upload. If QIO still asserts, try DIO 80 MHz.
  2. Boots once but no # QRM ready: after enabling USB CDC On Boot and uploading, the native USB re-enumerates, so the Monitor is stuck on the old port. Close the Serial Monitor, reselect Tools → Port, reopen at 115200, press RESET. If you also see a "USB Mode" option, set "Hardware CDC and JTAG".
  3. Easiest: if the board has a second USB-C (UART / COM) port, plug into it and monitor the usbserial/wchusbserial port at 115200 — that always shows the app output, no CDC setting needed.

Option B — digital caliper data port (precise, advanced)

If your caliper has a 4-pad data port under a cover, the ESP32 can read the exact number it shows. Precise, but the logic is ~1.5 V and the frame format varies by brand, so this is experimental and untested here.

Caveats. ~1.5 V logic is below many BSS138 level shifters' usable range; a per-line transistor stage or a caliper-specific reader may be needed, and the 24-bit format differs by brand. Verify on your bench before trusting it; in the firmware this mode is a documented stub.

How the ESP32 talks to the logger

The sketch prints at 115200 baud, one reading per button press. The logger (tab 1 → Connect ESP32) reads each line and either fills the field you are on or appends a row.

ESP32 printsthe logger does
20.01 (a bare number)fills the dimension field you have selected — use it like a numeric keypad, then click "Add specimen to log"
QRM,width,mid,20.01appends a full row (feature, location, value) with method = the "source" you picked
# QRM readyignored (banner / comment)

Device rows are tagged evidence_tier = PHYSICAL_CAPTURE; typed rows are OPERATOR_CONFIRMED. Confirm device readings against the display when it matters.

CSV columns (tidy / long format)

One row per individual reading. This is the format the Export button writes and that docs/engineering/templates/specimen_measurements.csv documents. Excel opens it directly; use a pivot table to view width-per-position etc.

Handoff to a later agent (not run here)

This page and the summarizer only record and describe the measurements. They do not change code. A later agent (your "CMC agent") could read this CSV and propose updates, for example:

  • group rows by specimen_id and feature, then compare the measured mean against nominal_mm;
  • flag critical features (width, slot_inner_width) whose deviation exceeds the chosen tolerance;
  • propose new nominal/tolerance constants or decision thresholds for review.
Guardrail: any such change is a proposal for a human to review. Measured data is evidence; it does not by itself re-tune the safety policy. Keep the raw CSV so every proposed change is traceable to real readings.

Summarize a CSV now, without any agent: python3 scripts/summarize_measurements.py your_file.csv prints per-specimen min/max/mean/spread and deviation from nominal, and can write a JSON summary with --json out.json.
